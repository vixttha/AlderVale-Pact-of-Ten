# Develop the Test Vault template

Open changes against `Test-Vault`. Update the files under `starter/` and exercise adoption through the public CI workflow. The original test harness is adapted here for three generic sample projects. Use the host project's chosen runner policy in any installation. The template itself is versioned separately from AlderVale's game and test suite.

## Add an approved version

1. Preserve the existing version folders and pinned source records. Add the new version to `versions/manifest.json` with a full commit and the directory to archive. Copy that directory's exact bytes into `versions/vX.Y.Z/`.
2. Run `python tools/graphify/version_maps.py <empty-output-directory>` in a Python 3.12 environment with the pinned packages in `tools/graphify/requirements.txt`. Copy the generated index and new version map into `Graphify HQ/` and include both in the review.
3. Run public CI on the review branch. It validates source archive completeness, rebuilds the maps, queries each archived file over Graphify MCP, and compares the generated bytes with the committed maps. It also runs the starter adoption fixtures.
4. After version approval, update the landing page and version index to identify the current archived version.

Map receipts describe archived source structure. Adoption results are separate test execution evidence.
