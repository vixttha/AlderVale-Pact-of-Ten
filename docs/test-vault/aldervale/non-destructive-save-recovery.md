The existing v1 fallback treated corrupt/unavailable data as an empty realm, and the old G28-003 test explicitly expected replacement. This candidate distinguishes missing, readable, recovery-required and storage-unavailable, blocks writes over unreadable data, offers realm-scoped retry/local export, and retains pending progress when its observed source differs. Export is a JSON wrapper containing the exact original storage string, not an import format. No reset or automatic repair. Legacy affinity records that are valid in the current prototype remain readable; the decoder's future-retirement diagnostics do not activate or rename any school. Signed-in cloud loading uses independent state rather than requiring readable guest data.

Limits: classification plus essential account checks is not exhaustive nested record validation; no production/cloud migration, full restore, schema version change, new registry or automatic mappings. Source comparison and pending source binding detect observed stale values but localStorage read/check/write is not atomic across tabs; cooperative serialization or transactional storage and stale-client strategy remain prerequisites for migration/cutover. Pending conflicts require a reviewed recovery strategy; no automatic replay onto changed data. Existing browser test changed from destructive replacement to exact original retention and other-realm isolation; unit cases cover invalid data, denied storage, lossless export, stale source and quota failure. Actual download UX and concurrent multi-page behavior require additional review. All execution uses public runners, no player data.
