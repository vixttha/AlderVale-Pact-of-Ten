# Engineering and release test catalog

Public CI uses synthetic data and demo services. Tests involving external production systems require their own isolated acceptance environment. Security checks here describe defensive invariants and use controlled fixtures.

| ID and category | Priority | AlderVale test ideas | First harness |
|---|---|---|---|
| E01 · Unit and boundary values | P0 | Decompose XP/pips for exact boundaries; isolated save transforms; numeric zero, caps and rounding; default values for omitted fields. | Vitest |
| E02 · Component and UI contracts | P1 | Dialog props and emitted commands; independent loading and error states; accessible names for tooltip-only controls; stable focus between rerenders. | Testing Library + Vitest |
| E03 · Static analysis and types | P0 | Build with pinned Node and TypeScript; reject illegal union members and stale imports; enforce consistent test types; lint Firestore rules and workflow schema. | tsc, ESLint, actionlint |
| E04 · Property-based testing | P1 | Generate legal decks and state transitions; no negative resources or nonfinite stats; idempotent claims; equivalent sequences under supported reorderings. | fast-check + Vitest |
| E05 · Model-based and state-machine testing | P1 | Match lifecycle from lobby to terminal; escrow listing lifecycle; quest state until reward; save retries and append operations match a reference model. | TypeScript state model |
| E06 · Combinatorial coverage | P1 | Pairwise realm, lineage, element and loadout; browser, viewport and input modes; guest, signed-in and reconnect states; exhaust critical small ownership matrices. | Parameterized Vitest/Playwright |
| E07 · Seeded simulations and balance | P2 | Same seed yields same results; health, win-rate and action-frequency distributions; minimum viable deck builds; Monte Carlo results stay within approved tolerances. | TypeScript + Python analysis |
| E08 · Authorization and policy | P0 | Guest/owner/other-player permissions; verify realm isolation at API and rules layers; ensure spectator data excludes private state; confirm credentials are never necessary for test jobs. | Firebase rules emulator + TypeScript |
| E09 · Privacy and data handling | P0 | Private profiles stay out of public reads; private Dorm contents stay restricted; logs omit tokens and unnecessary identifiers; public fixtures contain synthetic data only. | Emulator + log assertions |
| E10 · Interface and protocol contracts | P0 | Health/error response schema and content type; WS frame schema and backwards compatibility; client/server view agreement; stable behavior for absent optional fields. | Vitest + JSON Schema |
| E11 · Integration | P0 | Express request to Firestore commit; WS inputs to combat and receipts; cloud and guest storage adapter contracts; Three.js loader uses production-equivalent files. | Emulator + Vitest |
| E12 · End-to-end and smoke | P0 | Open built game and reach first interaction; model/text fallback; reload saved character; two isolated browser contexts complete a representative match. | Playwright |
| E13 · Regression | P0 | One named case per repaired audit defect; onboarding rollback; duplicate purchase/cancel; preserving selected card; regressions tracked with original affected commit. | Relevant owning suite |
| E14 · Negative and malformed input | P0 | Safe validation for missing fields or sizes beyond documented caps; invalid UI fields show accessible feedback; rejected requests leave state untouched; malformed fixture files fail predictably. | Table-driven API and component checks |
| E15 · Data, schema and referential integrity | P0 | Unique IDs across spell/creature/NPC/gear catalogs; every runtime reference resolves; reward tiers increase; invalid legacy records receive a safe repair path. | Vitest + schema validation |
| E16 · Migrations and compatibility of saves | P0 | Last supported versions load and save; interrupted upgrade resumes once; backups restore after failed migration; realm identity and currency stay intact. | Fixture matrix + emulator |
| E17 · Concurrency and atomicity | P0 | Parallel purchases and latest-balance reconciliation; two claims settle once; other players' writes survive unrelated updates; price/stock changes preserve escrow. | Firestore emulator + parallel tests |
| E18 · Fault injection and resilience | P1 | Inject transient database or asset failures; simulate delayed/reordered transport; UI recovers after motion interruption; retry budget caps and cancellation clean up state. | Isolated mocks and emulators |
| E19 · Differential and replay testing | P2 | Compare old and new mechanics with fixed fixtures; replay golden encounter actions; compare guest/cloud projections where contract matches; compare two browser outputs where results are invariant. | TypeScript and Python |
| E20 · Mutation testing | P2 | Verify tests reject a changed reward threshold; removed ownership check in a local mutant; swapped player projection; wrong card-remap arithmetic. | StrykerJS on scoped modules |
| E21 · Coverage and test quality | P2 | Measure branch coverage on risk paths; validate failure messages show case and seed; look for snapshot overreach; flag repeated skips/flaky cases and repair root causes. | Vitest coverage + CI logs |
| E22 · Rendering and visual regression | P1 | Rowan at rest/motion with stable camera; status icons and overlays; mobile safe areas; lighting tolerance plus numerical assertions; WebGL context fallback capture. | Playwright screenshots + Three.js |
| E23 · Accessibility and assistive tech | P1 | Automated names/roles/contrast; keyboard modal order and labels; NVDA/VoiceOver reading order; touch targets and zoom acceptance. | axe-core + manual AT |
| E24 · Browser, OS and device compatibility | P1 | Windows/Linux builds; Chromium, Firefox and WebKit smoke; touch and orientation; WebGL software vs hardware; manually confirm real iOS/Android input when applicable. | Standard runners + devices |
| E25 · Accessibility of 3D and audio cues | P2 | Important combat state available in text; shape and label supplement color; information survives muted audio; motion preference can disable nonessential motion. | Playwright + usability checklist |
| E26 · Performance and budgets | P1 | Time to title and first playable world; GLB transfer/parse budget; combat round latency; scene frame variance and memory trend after repeated transitions. | Lighthouse + Playwright + Vitest bench |
| E27 · Load, capacity and longevity | P2 | Isolated concurrent users; chat/presence updates under realistic activity; session cleanup after long matches; 60-minute restart/soak; compare latency and memory to baselines. | Controlled k6/Artillery environment |
| E28 · Offline, slow network and caching | P1 | Offline title and guest saves; dropped network during cloud save; asset retry after truncated transfer; cached version restored without mixing model/data revisions. | Browser offline controls + emulator |
| E29 · Logging and observability | P2 | Stable correlation IDs for failed purchase; test counters distinguish errors/skips; client and server timestamps can be reconciled; outage message is actionable. | Structured-log assertions |
| E30 · Build and reproducibility | P0 | Locked npm/Bun installs; clean checkout with case-sensitive paths; relative asset URLs and GLB byte hashes; validated startup with documented config. | Ubuntu/Windows runner + shell/Node |
| E31 · Dependency and supply chain | P1 | Pinned Actions references resolve; lockfile drift fails CI; check dependency advisories and notices; validate generated SBOM against lockfile; scan tracked config for accidental credentials. | Dependency review + policy checks |
| E32 · Release, deployment and rollback | P1 | Built artifact runs in isolated staging; wrong env config reports error; exact revision recorded; rollback preserves old saves; release workflow never deploys from a test branch. | Pipeline smoke + staged drill |
| E33 · Backup, restore and disaster recovery | P2 | Recover disposable backup with document counts and invariants; preserve independent realm keys; rebuild missing public projections once; measure restore time and data loss. | Emulator/isolated project + scripts |
| E34 · Cost and external services | P0 | Runner visibility guard; no live billing secrets; AI quota exhausted in mock; Firebase tests use demo project; intentional service requests tracked separately. | Workflow review + unit tests |
| E35 · Integrity of model and generated assets | P1 | Validate GLB header, buffers, rigs and clip names; missing texture/shader checks; hashes preserve approved assets; image/audio metadata stays within export budget. | glTF tooling + TypeScript/Python |
| E36 · Fuzzing and randomized workflows | P2 | Replay seeded legal state sequences; generate malformed save fixture inputs for local decoder robustness; randomized retries in a fake market service preserve invariants; shrinking produces a reproducible fixture. | fast-check/Hypothesis |
| E37 · UX and playtesting | P2 | First-time enrollment success and comprehension; contrast and tooltip clarity; failure recovery observed with opt-in testers; measure time and difficulty for returning players. | Manual protocol + anonymized results |
| E38 · Time, determinism and flakiness | P1 | Freeze clocks and random seeds; retry timer/backoff boundaries; run in timezone matrix; ensure tests wait for events and tear down listeners and intervals. | Vitest fake timers + CI |
| E39 · Legal and content provenance | P2 | Inventory asset author/source and redistribution status; third-party license notices present; store credits beside asset IDs; ensure release copies include applicable notices. | Manifest tests + manual review |
| E40 · Future integrations | Conditional | Native-client protocol contracts; database adapter migration parity; scheduled service behavior; mobile app lifecycle; new provider timeouts and quota isolation. | Contract fixtures + feature-specific toolchains |
