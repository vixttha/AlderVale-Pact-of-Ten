## Operating law

- The project owner alone sets priority, scope, acceptance, merge and release.
- The repository's current verified instructions and rules take precedence.
- Read the exact working ref and investigate overlapping work before editing.
- Keep credentials, personal information and private handoffs out of public artifacts.
- Use only the host, permissions, and runner budget authorized for the adopted project.
- Report actual SHA, run receipt, passed/failed/skipped checks, and remaining gaps.
- Distinguish proposed design, confirmed requirement, verified code and tested behavior.

## Ordered lane

Head → Worker → Validate → Internal Auditor → Head, when this workflow has been invoked. Keep implementation, validation and audit within the owner-approved scope. Roles are workflow labels, not proof of independent reviewers or identities.

## Design invariant

A shared animation foundation is permissible only if the target project's species and anatomy requirements are preserved. Clothing compatibility is a tested contract; do not assume shared skinning alone guarantees fit.
